## 四、`POST /api/verify` 落终态：不打架，但要写清适用范围

你的做法对，因为**工作流内的 verifier 不走这个接口**——引擎的 `n11` 节点直接调
`AgentRunner.run()` 产出报告文本，loop 节点靠 `exit_expression` 决定是否再来一轮。
只有前端手点「验证」才走 `POST /api/verify/{task_no}`。

所以两条路径互不影响：

- **API 路径**（人工触发）：落终态 → 任务不再被调度器判超时 → 不会假重试。对；
- **工作流路径**：任务状态由 `task_status` 事件驱动，`verify_task` 排的修正任务是**新任务**。

唯一要注意的：`verdict=failed` 但 `max_rounds` 未到时落 `failed` 是**合理**的——
这轮作业失败了，修正由 `create_correction_task` 排一条新任务来承接，不是同一个任务继续。

if key in SECRET_KEYS:

from sqlalchemy.orm import Mapped, mapped_column

class TaskEvent(IdMixin, TimestampMixin, Base):
    __tablename__ = "task_events"
    __table_args__ = (Index("ix_task_events_task_no_id", "task_no", "id"),)

    task_no: Mapped[str] = mapped_column(String(64), nullable=False, index=True, comment="任务号")

    event: Mapped[str] = mapped_column(String(16), nullable=False, comment="事件类型")

## 八、一个 PRD 自带的语义缺口（不改，但要知道）

默认工作流 `n11b.body_next = "n11"`（PRD 9.1 原文），意思是**回到验证**，不是**回到执行**。
所以 Self-Loop 两轮跑的是「同一批数据再验一次」，第二轮结论必然和第一轮一样，
靠 `round > 2` 退出。

真正干活的是**验证引擎的 feedback 策略**（`split`/`topup`）排修正任务——那条是另一个任务，
不在这个 loop 里。两条路径并存，不冲突，但演示时会被问。

**决定：保持 PRD 原文不改**（明天就交，不引入新偏离），文档记明。
如果评审追问，答案是「loop 节点驱动复验，修正动作由 feedback 引擎生成新任务，
两者分别对应 PRD 9.1 与 11.4.3，不是同一条路径」。
