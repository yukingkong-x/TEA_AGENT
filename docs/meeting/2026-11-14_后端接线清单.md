## 一、`app/bootstrap.py`（4 行）

```python
# 顶部
from .orchestrator.wiring import start_scheduler, stop_scheduler
from .verification.wiring import install as install_verification
from .workflow.wiring import install as install_workflow

def start_all(loop):
    ...
    install_workflow()          # 1
    install_verification()      # 2
    start_scheduler()           # 3（1s 一轮 daemon 线程）

def stop_all():
    ...
    stop_scheduler()            # 4
    ...
```

三个 `install/start` 都是**幂等**的，重复调用无副作用；内部失败只记日志不抛异常，
不会把 FastAPI 带崩（宁可功能 503，也不让平台起不来）。

## 二、三块接线各自做了什么

| 模块 | 提供 | 说明 |
| ---- | ---- | ---- |
| `workflow/wiring.py` | `EngineDeps`：读 `workflows.dag_json`、建 `workflow_runs`、回写状态、Agent 工厂、工具调用、WS 广播 | Agent 节点产出**顺带落 `agent_messages` 表并推 `agent_message` 事件**——之前没人写这张表，对话剧场是空的 |
| `verification/wiring.py` | `VerificationDeps`：取任务参数、取复测 3 读数、落 `verifications`、报警、排修正任务、读 run 出报告、落 `reports` | 取不到样本时**判低置信度转人工**，不拿默认值编达成率 |
| `orchestrator/wiring.py` | `SchedulerDeps`：任务快照、状态回写、WS、Agent 并发、设备在线 | `parallel_enabled` / `max_retries` 每轮从 settings 表读，改完下一轮生效 |

LLM 客户端也一起解决了：`workflow/wiring.current_llm()` 从 **settings 表**读
`llm_provider` + `llm_api_key`（解密后），主备双 provider，改 key 后下一次取用自动重建。
之前没有任何模块构建过 LLM 客户端，这块是我这轮补的。
