## 2. 需要你确认/配合的三件事

| # | 事项 | 说明 |
| - | ---- | ---- |
| 1 | **`tasks.status` 枚举缺 `needs_human`** | PRD 10.2 状态机、11.3「置信度 <60% → 转人工」都要落这个状态，但 `models/tasks.py` 的 `TASK_STATUS` 只有 9 态。建议加枚举值，DB 同步 `ALTER TABLE tasks MODIFY COLUMN status ENUM(...,'needs_human')`。不加的话验证引擎只能把结果塞进 `result_json`，任务页徽章出不来 |
| 2 | **`rejected` 的落库映射** | PRD 10.4 说熔断期内任务「直接返回 rejected」，但枚举里没有 `rejected`。调度器当前落 `dead` + `result_json={"rejected":"breaker_open","device":...,"retry_after_s":...}`。任务页要显示「熔断拒绝」徽章就按这个字段判，不要新增枚举值 |
| 3 | **`updated_at` 要跟着心跳刷新** | 调度器用 `updated_at + timeout_s` 判超时。`dispatched/running` 的任务如果执行中超过 `timeout_s` 没有任何回写，会被判超时——这是预期行为；但**设备 ack 回来时请顺手更新 `updated_at`**，否则真机慢一点就被误判超时 |

## 3. 已实现的语义（供你 review）

- **重试退避 2 / 4 / 8 秒**：PRD 10.4 的公式写作 `2^retry_count × 2s`（首退 4s），但同节例举与 15.2 剧本都是 2s/4s/8s，我按例举实现并在 `retry_delay_seconds()` 里写了原因。
- **设备离线时挂起重试**：退避到期但设备离线 → 保持 `retrying`、刷新 `updated_at` 重新计时、**不消耗重试次数**（PRD「离线则挂起重试」）。
- **熔断**：按设备记连续失败，threshold=3、open=300s；触发时发一条 `alert`（`source=device:<id>`、level=critical）；到期自动半开，成功即清零；`wiring.get_breaker()` 给设置页手动解除。
- **并行/串行开关**：`parallel_enabled=false` 时每轮只派 1 个任务（剧本 C 的对比就靠这个）。
- **每次状态变更都发 WS**：`{"type":"task_status","data":{task_no,run_id,from,to,reason,retry_count,score,assigned_agent,assigned_device},"ts":...}`，字段与 `docs/contracts/agent-data-contract.md` 一致。
