# 知识库语料（RAG 用）

这 5 篇是**自制语料**，不是标准原文，用途是把知识库填满、让检索有东西可命中。
每篇都在开头标注了来源，格式是 markdown（`.md`），后端可直接解析。

## 为什么不用行业标准的 PDF

实测过：从中国农科院茶叶研究所站点下载的《茶叶生产全程质量控制技术规范》编制说明
PDF（448 KB，PDF-1.7），上传后入库 **821 块**，但正文全是乱码：

```
"KJ Q H [>&~ ?Q\" &\n4{ ¶!(?Se* l < 9\np# ½ ÿÜÜ!73#'66#&'7#&'7&&..."
```

原因是这类 PDF 用了**字体子集化 + 自定义编码**，文字层没有可映射到 Unicode 的字符表，
任何基于文本层的解析器（pypdf / pdfminer / 自研解析）拿到的都是字形索引。
扫描件同理（整页是图片）。

**判断一份 PDF 能不能用**：拖进浏览器打开，鼠标能选中、能复制出正常汉字 → 可用；
只能看到图片或复制出乱码 → 不可用。

要演示「上传 PDF」这个动作，最稳的做法是**用 Word/WPS 自己写一页，导出为 PDF**
（文本型），而不是去下扫描版标准。

## 上传方法

设置页 → ⑦知识库管理 → 拖拽；或者：

```bash
curl -X POST http://127.0.0.1:8000/api/knowledge/upload -F "file=@docs/knowledge/01_茶园灌溉决策与土壤水分.md"
```

> Windows 的 Git Bash 用 `curl -F` 传中文文件名会失败（编码问题，返回空），改用
> PowerShell 的 `Invoke-WebRequest -Form`，或直接走设置页拖拽。
